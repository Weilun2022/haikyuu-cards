# 手機版移動卡片用兩段式 tap，不是單次 tap 或長按拖曳

手機點自己場上的卡進入「移動模式」後，點空格直接放；點**已佔用格**時，第一次點只標記 `movePendingZone` 並顯示左右分半提示（左=Guts／右=角色），要再點同一格一次、用點擊的 x 座標判斷點左邊還右邊，才真的執行移動。

## Considered Options

- **單次 tap 移動**：點格子就動，但一個已佔用格底下同時有「角色卡」跟「Guts 疊放的牌」兩種可移動對象，單次 tap 沒辦法讓使用者指定要移哪一個。
- **長按/拖曳判斷方向**：手機拖曳體驗容易誤觸、跟其他既有的長按手勢（長按 500ms 看詳情）衝突。
- **兩段式 tap（現行）**：第一次點只是「選定要移去的目標格」並亮出左右提示，不執行任何實際操作；第二次點同一格才用 `clientX` 判斷點左半（Guts）還右半（角色），呼叫對應的 `moveCard`/`moveGutsCard`。切去點別格會轉移 `movePendingZone`，不會誤觸。

## Consequences

`.zone-split-hint` 的左右提示層（`::before`=Guts 綠、`::after`=角色紫）z-index 要蓋過格子上原本的數值疊層（`.z-stat-overlay`），兩者同時顯示時必須讓 `.z-stat-overlay` 在分半提示狀態下 `display:none`，不然視覺會疊在一起看不清楚。之後如果要改成單次操作（例如加手勢區分），要先解決「同一格兩種可移動對象」這個根本限制，不能只是把兩段式邏輯簡化掉。
