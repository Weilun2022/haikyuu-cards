# 翻牌頂的同步節點以角色分流，捨棄舊分頁相容性

`peekNotif` / `peekReveal` 底下再分一層角色，寫成 `games/<room>/peekNotif/<role>`，兩個玩家各寫各的子樹。`placed` 的 key 用「放置流水號」，不是牌在牌堆裡的索引。

## Context

翻牌頂（peek）讓玩家看自己牌庫頂 N 張，每張可選落點：牌頂／牌底／手牌／棄牌。2026-10-24 以前，對手只看得到「翻了幾張」跟（公開模式）尚未處理的牌面，牌一被放置就從對手橫幅憑空消失，分不出它去了哪裡。

改版後的揭露規則由**落點**決定，不由模式決定：加入手牌、棄牌一律公開牌面；放回牌頂／牌底只有公開模式才亮。產品判斷來自使用者本人：「私看的時候我不用知道他看到哪幾張牌，但我需要知道他拿了什麼。」

這代表對手端要能追蹤每一張牌的去向，所以同步欄位從「一次性快照」變成「會被逐筆合併的落點紀錄」。

## Considered Options

### 同步節點

- **沿用共用節點 `peekNotif` / `peekReveal`（原設計）**：兩個玩家寫同一個 key，靠 payload 裡的 `by` 欄位辨認是誰翻的。改版前每次翻牌只有一次 `set` + 一次 `remove`，雙方同時翻牌時後開的覆蓋先開的，症狀只是「有一方的橫幅沒顯示」，短暫且無害。
- **共用節點 + 開翻前檢查對手是否正在翻牌**：保留舊分頁相容性，但擋不住真正同時按下的競態，而且對手的節點若因故殘留，會永久擋住自己開翻。
- **以角色分流 `peekNotif/<role>`（採用）**：從路徑上就不可能互相干擾。

### `placed` 的 key

- **牌堆原始索引**：`_peekCards` 全程不刪元素所以索引穩定，同一張卡在同一次翻牌出現兩次也分得開。但索引就是「牌頂數來第幾張」，對手讀一下 `gameState` 就知道你挑了哪一張，私看等於只在 UI 層遮住。
- **放置流水號（採用）**：同樣唯一、同樣分得開重複卡，而且它本來就是要公開的資訊（橫幅照處理順序排）。

## Decision

角色分流 + 流水號當 key。理由是改版後 `placed` 是**逐筆合併**（`update({'placed/<seq>': …})`）而不是整包覆蓋，共用節點的撞擊後果從「少顯示一個橫幅」升級成「我的落點被掛到對方名下，對手橫幅顯示錯誤資訊」；而且收尾後橫幅會多留 6 秒（見下方 Consequences），重疊窗口比以前更長。資料正確性優先於舊分頁相容。

## Consequences

**舊分頁看不到翻牌橫幅。** 節點結構從 `{by, count, ts}` 變成 `{host: {...}, guest: {...}}`，舊版程式讀 `data.peekNotif.by` 得到 `undefined`，判斷失敗就不顯示。不會報錯、不會顯示錯誤資訊，重新整理即可恢復。這是刻意用相容性換資料正確性，**不是疏忽**——如果之後有人想「修」回共用節點，請先讀完上面 Considered Options。

其餘連帶的設計約束：

- **`update()` 一律寫到 `placed/<seq>` 子路徑**，不可寫 `update({ placed: {...} })`——後者會把同一次翻牌已經放好的其他紀錄整個蓋掉。
- **不該公開的牌，`img` 欄位整個不寫**，不可寫 `undefined`，RTDB 不吃。
- **RTDB 會把連號整數 key 的物件還原成帶 `null` 空洞的陣列**，讀 `placed` 的地方一定要 `filter(Boolean)`，否則排序／計數會拿到 `null` 並讓例外一路竄進 `syncUI`。
- **橫幅收尾的時間用本機收到 `done` 的時刻算**，不可用寫入端的 `Date.now()`。兩台電腦時鐘差幾秒，最後一批落點就會在對手還沒看到時被判定逾時。
- **斷線時 `onDisconnect().remove()` 會把節點刪掉**，重連後必須重發整包（`_peekBase` + `_peekPlaced`），否則對手後半段全看不到。重發掛在 `_startPresenceWatch()` 的 `.info/connected` 監聽裡，跟 presence 走同一條路（見 [0002](0002-mobile-reconnect-persistent-presence-watcher.md)）。
- **復原（undo）要把自己的翻牌節點刪掉**。翻牌是一次 `saveUndo` 蓋住整輪，復原等於整輪沒發生，橫幅不能還掛著已撤銷的「進手牌」。
- **離開房間要清掉 linger 計時器**，它抓著舊房間的 ref，6 秒內重進同一間房會砍到新節點。
