# 雲端同步衝突處理用 last-write-wins，不做欄位級 3-way merge

雙邊都改到同一副牌組時，直接整份用時間戳比較新舊、新的整個覆蓋掉舊的，不嘗試合併雙方改動、不建立「衝突副本」。

## Considered Options

- **欄位級 3-way merge**（baseline/本機/雲端三方比對，逐欄位合併）：曾經實作過（`357bbdb`），結果造成「衝突副本一直重新冒出來刪不掉」的使用者體驗問題，已在 `c1c4263` 移除。
- **Last-write-wins**（現行）：邏輯簡單、每副牌組永遠只有一份「最新版」，沒有衝突副本這個概念。代價是雙邊真的同時修改時，較舊那份的改動會直接消失、不提示、不保留。

## Consequences

換裝置第一次同步（本機沒有 baseline）時，「沒有 dirty 紀錄」容易被誤判成「本機比較新」，曾經導致新裝置的空白內容覆蓋掉雲端資料（見 `js/cloud-sync.js` 2026-07-24 的修法）。之後任何調整 LWW 時間戳比較邏輯，都要記得這個邊界情況。
